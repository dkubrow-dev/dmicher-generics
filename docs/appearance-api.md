# Общее оформление и поведение окон

Публичный API 1 содержит `generics.appearance`. Generics регистрирует клиентское меню «Оформление и окна». Выбор действует на все окна dmicher в текущем браузере; настройки других участников не изменяются.

## Контракт потребителя

Обычное приложение добавляет класс `dmicher-window` и свой предметный класс через `generics.theme.createWindowThemeController({windowClass})`. Общие переменные `--dmicher-*` задают цвета; продуктовые стили отвечают за компоновку своего содержимого. Собственный переключатель глобальной темы продукту не нужен. `generics.appearance.getTheme()` возвращает `dark` или `light`.

`appearance.openSettings()` открывает единое окно настроек. «Сохранить» применяет значения и оставляет окно открытым; запись не вызывает повторного рендера и не стирает изменения, внесённые во время ожидания. `appearance.openHelp(pageId, anchor)` открывает эксплуатационную справку Generics; доступные страницы: `appearance`, `windows`, `custom-style`, `settings` и обязательные нижние страницы. Контент справки Generics относится только к его функциям; справки других модулей остаются у них.

Старый `createWindowThemeController({windowClass,getTheme})` совместим: после запуска общей службы настройка Generics имеет приоритет перед старым getter и аргументом `apply(value)`. Для миграции потребитель может передать **явно сохранённое**, а не дефолтное значение: `appearance.adoptLegacyTheme(value, priority)`. До первого `ready` выбирается кандидат с наибольшим приоритетом. Уже выбранная общая тема не перезаписывается. Generics не знает ID и имён настроек продуктов.

## Прилипание

Клиентские флаги `snapScreen`, `snapWindows`, `snapCorners`, `snapCenters`, `snapCascadeRightButton` по умолчанию включены. Углы и центры доступны при включении хотя бы одного вида прилипания и относятся только к разрешённому виду цели.

Служба получает Application через стандартные render/close hooks Foundry V1/V2. Она реагирует только на пользовательский перенос за `.window-header`; свой handle потребитель явно маркирует `data-dmicher-window-drag`. Наличие маркера добавляет прилипание к уже реализованному переносу, само по себе оно не включает перенос. Кнопки, поля и элементы управления заголовка исключены. Встроенные панели помечаются `data-dmicher-docked="true"` и не участвуют в прилипании.

Порог — 12 CSS-пикселей. Расчёт использует исходное положение и полное перемещение курсора, поэтому прилипание не накапливает смещение, а отлипание происходит при выходе за тот же порог. Выбирается ближайшая внешняя сторона другого окна или внутренняя сторона экрана, затем допустимое выравнивание вдоль этой стороны. Программные `setPosition`, изменение размера и восстановление рабочих столов не запускают прилипание. Вынесенное окно использует свой `ownerDocument`, размеры его браузерного окна и соседей в нём.

Подписки на перенос снимаются при отпускании/отмене указателя, потере фокуса и закрытии приложения; общий `dispose` снимает hooks и слушателей. При переносе окна между документами Foundry 14 контроллер сохраняет тему и обновляет слой CSS в новом документе.

### Каскады окон

У приложения должен быть постоянный `app.id` (резерв — `options.id`, затем ID корневого элемента). Повторный живой ID не присваивается другому окну. Связь создаётся только после фактического пользовательского прилипания левой кнопкой к зарегистрированному окну dmicher; случайное соседство или программный `setPosition` не создаёт связи. Связи двусторонние и хранятся явно. Перенос правой кнопкой за заголовок перемещает всю связную группу с одинаковым смещением, обход каждого ID выполняется один раз. Каскад ограничивается размерами текущего браузерного окна как целое. Одиночный правый клик сохраняет обычное контекстное меню; меню подавляется лишь после фактического переноса каскада.

Перенос левой кнопкой отделяет выбранное окно, сохраняя остальные связи группы. Изменение размера, закрытие, встраивание панели и перенос элемента в другой `ownerDocument` разрывают связи этого окна. Отключение `snapWindows` очищает все связи; отключение `snapCascadeRightButton` прекращает перенос правой кнопкой, сохраняя существующее прилипание. Программное изменение положения не двигает соседей и удаляет переставшие быть соседними связи. Прилипание никогда не связывает разные окна браузера.

`appearance.getWindowLayout()` возвращает замороженный снимок `{windows: [{id,left,top,width,height}], links: [{from,to}]}`. Каждая двусторонняя связь представлена один раз. Это контракт чтения для будущего сохранения рабочих мест: он не создаёт окна, не содержит продуктовых данных и не восстанавливает каскады автоматически. Потребитель связывает ID со своими собственными командами открытия; текущая версия не обещает сохранение каскадов после перезагрузки.

## Слой Premium

`customStyles` хранит текст выбранного файла в клиентской настройке Generics. Бесплатный метод возвращает пустую строку. Premium поставляет чистую синхронную реализацию `resolveCustomStyles(base, css)` через отдельный дескриптор целевого модуля `dmicher-generics`, API 1. Генерик не проверяет лицензию сам и не читает API Premium напрямую. Статус другого лицензированного модуля не предоставляет доступ к этому расширению.

При отсутствии, несовместимости или отзыве расширения слой немедленно снимается, сохранённый текст не удаляется. Восстановление доступа снова применяет сохранённый слой. Импорт доступен только при активном расширении; удаление ранее сохранённого слоя доступно всегда. Запись настроек не проводится через fallback методов значений.

Файл ограничен 64 КиБ. Native CSSOM разбирает его до помещения в `@scope (.dmicher-window)`, не позволяя незакрытой скобке вывести правило за пределы окна. Поддерживаются обычные правила, `@media`, `@supports`; внешние `@import`, глобальные правила шрифтов/анимаций и CSS nesting отклоняются. Оформление самого корня окна сохраняется отдельным вариантом селектора. Подготовленный стиль кэшируется по содержимому, добавляется после встроенного оформления и удаляется при `dispose`.

## Проверка

`npm test` проверяет геометрию, независимость общего оформления от старых настроек, миграцию, отсутствие Premium, отзыв/возврат доступа и освобождение hooks. `scripts/verify-appearance-browser.mjs` дополнительно проверяет настоящий DOM браузера, работу `@scope`, перенос мышью и применение/снятие слоя. Для него задаются `PLAYWRIGHT_PACKAGE` и `BROWSER_EXECUTABLE` на уже установленные инструменты разработки; они не становятся зависимостями устанавливаемого модуля. Скрипт не подключается к живому миру Foundry.
